## Final finding register

### A001 — Browser submission can send pre-review text

**Critical · Confirmed defect · P1**

**Evidence:** Approval changes proposal_text but leaves humanized_text and typing_plan intact. Both browser dispatchers and both proposal editors prefer humanized_text. Reverting a version also changes only proposal_text.

**Code:** [backend/app/routers/proposals.py:162](/home/dima/Work/Projects/gighound/backend/app/routers/proposals.py:162); [backend/app/routers/proposals.py:68](/home/dima/Work/Projects/gighound/backend/app/routers/proposals.py:68); [worker/handlers/upwork_proposal.py:88](/home/dima/Work/Projects/gighound/worker/handlers/upwork_proposal.py:88).

**Proof:** test_edited_approval_keeps_old_browser_text.

**Impact:** A reviewer can correct price, promises or confidential wording and still send the old draft. Reloading the editor can also show the old text.

**Remediation/acceptance direction:** Persist one immutable approved content snapshot/hash, invalidate derived text/plans on edit/revert, and verify the exact text in the final form before dispatch.

### A002 — Legacy submission APIs bypass dispatch idempotency and platform binding

**Critical · Confirmed defect · P1**

**Evidence:** The main submit endpoint conditionally claims approved→submitting. The legacy Freelancer route leaves the item approved after bidding; repeating it calls place_bid again. Neither legacy route checks item.platform against its endpoint. Upwork legacy dispatch has no atomic claim.

**Code:** [backend/app/routers/adapters.py:88](/home/dima/Work/Projects/gighound/backend/app/routers/adapters.py:88); [backend/app/routers/adapters.py:161](/home/dima/Work/Projects/gighound/backend/app/routers/adapters.py:161); [backend/app/routers/proposals.py:531](/home/dima/Work/Projects/gighound/backend/app/routers/proposals.py:531).

**Proof:** test_legacy_bid_repeat_and_wrong_platform.

**Impact:** Duplicate external bids, concurrent submissions and submissions to the wrong platform are possible through authenticated APIs even if the normal UI does not call them.

**Remediation/acceptance direction:** Route every submission entry point through one account/platform/request-type-bound state machine and idempotency key; retire duplicate implementations.

### A003 — HTTP retries replay potentially committed mutation requests

**High · Confirmed defect · P1**

**Evidence:** Retry behavior is independent of method: transport failures and 429/5xx retry POSTs up to five attempts. No external idempotency token or reconciliation occurs.

**Code:** [backend/app/adapters/ratelimit.py:140](/home/dima/Work/Projects/gighound/backend/app/adapters/ratelimit.py:140); [backend/app/adapters/freelancer.py:188](/home/dima/Work/Projects/gighound/backend/app/adapters/freelancer.py:188).

**Proof:** test_mutating_post_is_retried.

**Impact:** A remote service may commit a bid before its response fails. A retry can repeat the action; actual platform duplicate rejection was not tested.

**Remediation/acceptance direction:** Retry reads automatically. For writes use provider-supported idempotency or record an uncertain outcome and reconcile before retry.

### A004 — The stealth reaper replays submissions and fails to close exhausted proposals

**Critical · Confirmed defect · P1**

**Evidence:** Every old claimed task is reset to pending regardless of task type or whether a submit click occurred. At the reclaim limit only the task becomes failed; its queued_for_browser proposal and agency record remain outstanding. There is no claim generation/fencing token.

**Code:** [backend/app/tasks.py:615](/home/dima/Work/Projects/gighound/backend/app/tasks.py:615); [backend/app/tasks.py:636](/home/dima/Work/Projects/gighound/backend/app/tasks.py:636).

**Proof:** test_reaper_requeues_irreversible_submission; test_reaper_final_failure_strands_proposal.

**Impact:** A worker dying after a successful click can cause another worker to click again. Exhaustion leaves a proposal permanently in flight. A completion/reaper race can also resurrect work.

**Remediation/acceptance direction:** Separate replay-safe reads from external writes, record dispatch intent before clicking, fence each lease, and reconcile uncertain writes instead of requeueing them.

### A005 — Task publication and proposal status are committed separately

**High · Confirmed defect · P1**

**Evidence:** enqueue_stealth_task commits a pollable task before submit_proposal sets queued_for_browser. Fiverr dispatch has the same ordering. The completion consumer updates a proposal only when it is already queued_for_browser. Agency StateStore helpers also commit internally.

**Code:** [backend/app/stealth.py:59](/home/dima/Work/Projects/gighound/backend/app/stealth.py:59); [backend/app/routers/proposals.py:601](/home/dima/Work/Projects/gighound/backend/app/routers/proposals.py:601); [backend/app/routers/gigs.py:456](/home/dima/Work/Projects/gighound/backend/app/routers/gigs.py:456).

**Proof:** Source interleaving; not reproduced under real concurrent Postgres workers.

**Impact:** An early worker result or process failure between commits can strand/overwrite state; an approved or submitting proposal can have an executable task already published.

**Remediation/acceptance direction:** Make task creation, approved snapshot and proposal transition one transaction. Remove helper-level commits and publish asynchronous work via an outbox.

## Strengths retained after adversarial review

- The main submission route already has an atomic approved→submitting claim; fix the other entry points around it rather than discarding the design.
- Normal tenant reads use scoped/get_owned; referenced search-profile and gig-template IDs have ownership checks. The foreign filter reference is a specific exception, not evidence that all tenant APIs leak.
- Vault encryption, mandatory production secret configuration, JSON-only Celery messages and non-root containers provide useful foundations. Worker session folders/files have restrictive modes.
- Job ingestion has a unique external identity constraint, bounded fuzzy candidates, transaction rollback on insert races and a persisted partial unique proposal index.
- Generation runs off the ingest request path; failure rows, bounded automatic retries and task fan-out already exist. They need durable intent and exclusive execution.
- There are explicit uncertain submission states and post-click exception handling on part of the Upwork path. The surrounding completion/recovery protocols need to preserve that intent consistently.
- Frontend build/typechecking and large backend/worker regression suites pass; API timeouts, draft persistence and reconnect reloads are implemented. The first-event bug and end-to-end contract gaps are narrower than a blanket claim that live updates/draft recovery do not exist.
- Runtime dependency locks have hashes; GitHub actions are SHA-pinned; current scanner results contain no reported vulnerabilities.
