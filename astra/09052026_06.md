## Implemented in this continuation (verification still ongoing)

- Durable `User.session_version` and `AuthTransaction` JWT revocation/OAuth state; logout and password changes remain effective without Redis. Single-use OAuth is bound to authenticated user, account and configured redirect. Non-default Freelancer principals no longer overwrite default credentials. Token schema carries refresh metadata. Password enrollment is rejected and removed from the selectable UI options.
- WebSocket tickets retain the originating auth token, revalidate every ping/15-second timeout, and release the DB session while idle. Browser JWT query-string fallback was removed; Redis outages reconnect later.
- Browser HTTPS host/origin/cookie allowlists apply to every intercepted request, and service workers are blocked. This intentionally restricts external CDNs; network-level private-address/DNS-rebinding protection is still an operator deployment dependency, not proven by hostname checks.
- Durable generation work table, bounded claims, expiration/fencing and broker-outage replay. Job plus generation intent commits before publication. Both generation success and failure writes check the active lease and refuse to overwrite a reviewed row.
- Discovery distinguishes failed from successful empty searches; per-profile pacing prevents same-platform profile starvation. Upsert refreshes observations, expiry is checked, and profile-local negatives no longer globally exclude jobs accepted by another profile.
- Outcome writes lock proposals/templates, repeat outcomes are no-ops, and corrections recompute template totals. Rate learning reads attributable confirmed outcomes with matching currency and billing unit; legacy untyped aggregates are excluded. Bid calculations convert rate-card currency to job-native units and keep unknown currency unknown. Static FX still requires dated provenance/live-rate work before financial precision can be claimed.
- `submitted_at` records observed confirmation separately from approval; follow-ups and submission trends use it. Historical unknown timestamps stay null. Stable provider client IDs replace anonymous cohort identity. Generic “contract” no longer confirms hiring and identifier matching uses boundaries.
- Typed schemas reject non-finite numbers and bound nested input. Filter foreign references and preview invalidation are tenant scoped. New agency audit rows carry tenant ownership; ambiguous historical ownership remains null.
- Digest routing ignores global `DIGEST_TO`. Delivery requires an operator-verified `{user_id: registered_email}` mapping in `GIGHOUND_VERIFIED_DIGEST_RECIPIENTS`, a durable per-window attempt reservation, and an SMTP timeout. Uncertain SMTP attempts are not blindly retried. A self-service email verification journey remains a future replacement for operator enrollment.
- Modal focus trapping/restoration, validation alert semantics, URL-backed main navigation, proposal-list request ordering, session/password messaging and currency labels.
- Material approval snapshots record exact text/bid/period/currency/unit/destination/account configuration. Proposal revisions support stale-review rejection in the UI. Submission checks snapshot equality before and after claiming. Legacy approvals require renewed review. A return-to-review API/UI action is available. Compatibility clients omitting expected_revision are still accepted; strict API-wide revision enforcement remains open.
- New tasks bind the unique browser account ID at insertion. Account platform/principal are immutable. Ambiguous/missing/disabled bound accounts fail execution checks. Historical unbound tasks and all adapter account-selection paths still need comprehensive migration/enforcement review.
- Explicit manual circuit stops stay open through cooldown. The worker poll prioritizes write kinds. Worker session purge erases cookies/local storage/screenshots after tasks while retaining only non-secret fingerprint metadata; crash leftovers and deletion acknowledgments still need deployment-level verification.
