# September 13, 2026 — Tracked seller identity and metrics attribution

## Confirmed defect
`enqueue_metrics_scrape` grouped all tenant listings by platform, without retained seller identity. Multiple Fiverr/Upwork accounts could therefore mix listings in one dashboard task. Registered listings did not store an account. Worker metric uploads checked only task membership and platform/tenant, so assignment changes could not invalidate old results.

## Implementation
- Migration `b39fa46fd835` adds explicit account ID, immutable account identity snapshot, and assignment version to tracked gigs. Account snapshots intentionally survive account deletion. Existing gigs remain unassigned (no guessing/backfill).
- Registration accepts an optional owned/enabled browser account. The owner-scoped assignment endpoint supports assignment/clearing and checks the expected version under a row lock.
- Gig Manager exposes a seller assignment control on the listing's metrics panel, including a manual-only unassigned option.
- Dashboard collection groups listings by exact platform/account/identity. Unassigned, stale, disabled, unsupported or paused listings are not included in executable tasks. Manual scrape response/audit returns skipped listing IDs, and the UI reports dashboard task counts rather than calling them gig counts.
- Each task records the listing assignment version. Worker uploads lock the listing and compare its current account, identity and assignment version before accepting metrics. Previously queued results cannot overwrite a changed assignment, including a switch away and back. Legacy tasks without a version require fresh collection.
- Manual owner-entered metrics remain available without a connected seller.
